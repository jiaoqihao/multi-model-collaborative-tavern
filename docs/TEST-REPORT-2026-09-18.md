## 真实 API 联调

- 协议：OpenAI 兼容，地址 `https://api.deepseek.com/v1`。
- 本次列表返回 `deepseek-flash`、`deepseek-v4-pro`，实测使用 `deepseek-flash`。没有沿用不可用的旧模型别名。
- 本轮共 79 次 HTTP 请求，其中 73 次聊天请求、6 次模型列表查询；不包含本地注入的假响应。
- 服务商返回用量累计：输入 92,472 Token，输出 31,174 Token，共 123,646 Token。未换算费用，以账户账单为准。
- 使用合成故事，不使用用户导入的角色卡、私人故事或线上数据库。单次脚本上限为 40 次请求；完整 Worker 测试上限为 18 次。

### 分阶段验证

第一轮 9 个检查中 7 个通过：模型发现、结构化连接、空故事、均衡私聊及记忆写入、经济双角色、干净父快照重生成、过滤后重排。另两项为：

1. **逐字复述断言不通过。** 复查后，导演输出中仍包含正确口令，但将询问解释为试探，要求角色拒绝复述。角色可以记得却不说出口，这个断言混合了记忆能力与人物合作意愿，不能直接判为记忆丢失。后续改用合作型合成记录员，在完整路由测试中成功复述编号。
2. **精细复核达到 2,400 Token 测试输出额度。** 生产适配器正确识别截断并拒绝继续。采用默认 5,000 Token 上限的补测完成了复核、旁白和记忆更新。两次输出并不相同，因此只说明低额度有截断风险，不保证提高上限一定解决。

复查还观察到裁决输出将线索写成持久化字段 `status`，遗漏协议要求的 `action`；现有重试携带字段错误后可恢复。导演有时提前编写角色台词、补充玩家姿势，显示结构合法并不等于语义边界正确。

### 完整路由验收

运行实际 `app/api/tavern/route.ts`、生产引擎与模型适配器，连接真实服务商，使用一次性 Miniflare Workers/D1。测试身份由封装入口注入，不把它当作生产登录验证；生产认证另由本地接口套件验证。

为避免保存真实密钥，临时数据库仅保存加密的假凭据，真实凭据在测试出站边界中从内存附加。其余模型请求由实际适配器生成，D1 保存与 SSE 回包使用真实业务代码。

最终一轮验证：

1. 模型配置回包不暴露凭据。
2. 在记忆阶段人为返回两次无效 JSON：整轮无回合提交，故事 revision/head 不变，前四阶段已缓存。
3. 对同一请求重试：跳过已完成阶段，仅继续记忆调用；正文、快照、事件记录保存成功，阶段缓存清理。
4. 重放已完成请求：没有新增服务商调用。
5. 下一回合准确复述测试编号，并完成保存。
6. 回退序章恢复完整根状态，两条历史回合保留。

前两次完整路由运行分别在失败缓存检查、后续回合生成时中止。早期工具没有保留足够的失败详情，不能臆断其根因；最后一次通过不覆盖这些失败记录，稳定性仍需多种模型、输入和重复批次评估。

## 已确认问题与建议顺序

### P1：经济模式合法事件会在记忆整理阶段失败

位置：`lib/tavern/engine.ts` 经济模式 `writeCardMemoryDelta` 分支，与 `lib/tavern/cards.ts` 的增量记忆约束不一致。

| 合法裁决输出 | 下游处理 | 实测 |
| --- | --- | --- |
| 单条 400 字事件 | 直接放入 `factsAdd` | 通过 |
| 单条 401 字事件（裁决允许最多 2,000 字） | `factsAdd` 单条最多 400 字 | 失败 |
| 三条各 400 字事件 | 拼接为 1,202 字 `summaryAppend`，上限 1,000 | 失败 |
| 401 字剧情线索（裁决允许最多 1,000 字） | `openThreadsAdd` 单条最多 400 字 | 失败 |

四项探针均确认源故事未改变。失败发生于确定性代码，不是模型返回了非法裁决结构；重试相同缓存也无法解决长度冲突。

建议：为经济模式建立独立的、符合记忆限制的摘要及事实压缩步骤；保留原始事件记录，避免直接截断关键事实；对过长待办使用稳定标识或受限摘要，确保后续 resolve 能匹配。补齐边界回归后再发布。

### P2：模型语义越界与结构波动

导演偶尔提前生成角色回答、推断提问动机；裁决偶尔混用持久化结构与增量协议。建议分开约束感知分发和行动生成，在线索协议中显式对比合法与非法字段，并将“记忆传入正确”“事实回忆正确”“角色愿意复述”设为三类独立检查。

### P2：输出额度及可观测性

精细模式应独立设置复核输出预算；截断错误应与 JSON 字段错误区分。对外保持脱敏错误，内部仅记录阶段、字段路径、finish reason 和额度，不能记录密钥或私人故事。

### P3：前端体积与长标题布局

构建存在超过 500 KB 的包体警告。桌面截图中超长无空格测试标题触发了侧栏水平滚动，建议后续完善省略与宽度约束。本次未做移动端视口或视觉回归验收。
