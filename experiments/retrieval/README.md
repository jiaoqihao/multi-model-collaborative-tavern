# 中文剧情混合检索试验

这是独立离线试验，生产 API 不导入此目录，不改变线上检索、D1 schema 或模型配置。仅使用仓库内人工编写的合成材料，不读取 `.dev.vars`、角色库、导入卡片和用户故事。

已完成的真实模型对比见[第一轮实测结果](RESULTS.md)，包含失败案例和下一轮验证建议。

## 复现

```powershell
npm install --prefix .tmp/retrieval-runtime @huggingface/transformers@3.8.1 --no-audit --no-fund
npm run experiment:retrieval
# 主站不可达时，显式使用公共模型镜像：
npm run experiment:retrieval -- --mirror
# 首次成功后，只使用已缓存的真实向量重跑排序：
npm run experiment:retrieval -- --offline
```

首次运行下载公开模型，固定使用下载时解析得到的 Git revision，并在报告中记录。推理在本机 CPU 完成，合成文本不发送给 embedding API，不产生模型 API 费用。模型、独立运行环境和向量缓存仅写入已忽略的 `.tmp/`，逐题报告写入已忽略的 `outputs/retrieval/report.json`。`--offline` 复用输入指纹一致的向量，复核检索排序；报告中的 embedding 耗时来自初次编码，并非每次重新测量。

## 方法与预先设定的门槛

- 数据：24 个主题，每个主题包含相关经历、一条干扰经历、直接问题和语义改写问题；另加 3 个生命周期问题。总计 56 条候选记忆、51 个问题。
- 额外干扰：其他用户、故事、角色、兄弟分支和未来分支各一条高相关记录。排序前过滤，禁止向量分数覆盖知情范围。
- 关键词基线：直接复用 `selectMemoryEvidence` 原有排序规则；全部方法共用预过滤后的候选集。
- 纯向量：384 维多语言 MiniLM 句向量，均值池化、归一化、余弦相似度。
- 混合：关键词排序与向量排序使用等权 Reciprocal Rank Fusion，固定 `k=60`，未按主题或测试结果调权重。
- 全部方法使用最多 3 条、900 估算 Token 的相同输出限制；另在 180/450 Token 下分析预算敏感性。预算计算包括序列化记忆元数据，不代表服务商精确 tokenizer 或整轮请求大小。
- 指标：Hit@1、Recall@3、MRR@3、nDCG@3，及估算 Token、排序耗时、向量生成耗时、越界数量。当前每题一个标准答案，Recall@3 等同于 Hit@3。
- 进入下一轮独立验证的门槛：改写组 Recall@3 提升至少 10 个百分点、直接组 Recall@3 下降不超过 5 个百分点，越界为零。通过仅说明值得继续试验，不代表获准或适合直接上线。

## 已知局限

这是小规模、自行编写语料的可行性试验，不是独立盲测或公开 benchmark。查询与答案同源，不能据此预测用户真实故事的效果。相关经历的 importance 和 scope 固定，未覆盖生产中复杂的重要性差异；也没有未知问题拒答、多答案、长卡片、跨语言或大规模并发测试。

历史意图由评测标签显式提供，未评估自然语言意图分类；生产必须从当前分支快照构建事实有效状态，不能把其他分支改写后的 status 直接复用。权限过滤是程序契约测试，不能保证上游模型标注的可见范围一定正确。

本地 CPU 的 embedding 和排序耗时不等于 Workers 性能，也不包含外部 embedding API 网络延迟。本次不选择向量数据库，不接入在线服务，不评价生成正文的实际一致性。下一步需要独立编写的更大测试集与受控故事回放。

## 失效保护

向量缺失、维度不一致、模型版本不一致、非有限值或零向量时整次回退关键词排序；缓存与模型 revision、文本指纹绑定。索引键包含用户、故事、角色、来源回合与记忆 ID。相关边界由 `tests/hybrid-retrieval.test.ts` 验证，测试中的手工向量只用于正确性测试，不用于效果报告。
