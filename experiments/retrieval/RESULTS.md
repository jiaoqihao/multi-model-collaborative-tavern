# 第一轮实测结果

结论：真实语义向量对中文剧情改写查询有明显帮助；当前等权 RRF 混合检索优于现有关键词基线，但前三条召回弱于纯向量。值得继续独立验证，暂不将这一配置直接接入线上。

本轮使用本地 CPU 上的 `Xenova/paraphrase-multilingual-MiniLM-L12-v2`，固定 revision `2c4055b12046f11709e9df2c122e59ffbdc2f900`，q8 量化、384 维、均值池化和归一化。由于主站连接超时，模型通过公共镜像下载，推理在本机完成。51 个合成问题、56 条合成记忆，没有真实用户数据。未训练或按结果调整检索参数。

## 失败案例决定下一步

- “她为什么不再相信我？”：纯向量首条命中失约经历；混合前三条却是新会面地点、尊重决定边界及其干扰记录。
- “我还欠谁一笔钱？”：纯向量首条命中摆渡人垫款；混合被救人报答、送匣子与家书等记录占据。
- “最初的见面地点是哪里？”：旧地点已被历史模式正确放进候选集，纯向量命中；混合仍遗漏。可见“允许查旧事实”与“能把正确旧事实排上来”是两件事。
- “给她准备点心需要忌口什么？”：本模型的纯向量与混合都未命中过敏经历。模型能力和代词／场景消歧也需改善，单独调整融合权重不能保证解决。

RRF 当前对完整关键词排序与完整向量排序等权融合；当关键词缺少有效匹配时，仍会把时效等非语义排名当成相同强度的证据。因此下一轮优先评估“有真实词项命中才参与融合”、两路召回并集后重排、以及历史查询的时间过滤。当前数据已用于分析，应视为开发集；新方案必须在另外编写的主题隔离测试集上比较，避免反复调整直到这 51 题变好。

## 成本与边界

首次模型载入（含文件下载／初始化）约 15.5 秒，56 条记忆批量编码约 136 毫秒；51 次单条查询编码 P50 约 4.6 毫秒、P95 约 14.5 毫秒。这是当前本机 CPU 的小样本测量，不代表 Workers 性能或外部 API 延迟，也不包含生成正文的模型开销。缓存复跑的排序 P95 均小于 1 毫秒。

预算降至 180 估算 Token 时，全题 Recall@3 分别为 66.7% / 84.3% / 76.5%；450 与 900 Token 结果一致。由于本轮文本短且最多返回三条，900 Token 上限通常未成为约束，不能外推到长角色卡。

独立运行环境、模型与向量留在 Git 忽略目录；仓库只包含合成语料、试验代码、边界测试和不含向量的[逐题结果](results.local-minilm.json)。已有 43 项测试通过，包括新增的权限与分支预过滤、生命周期、向量失效回退和预算边界；缓存离线复跑成功。线上算法、数据库与部署均未因本次离线试验改变。
